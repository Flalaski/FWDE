# Progress (Updated: 2026-11-02)

## Done

- **2026-11-02: Window Registry — one classification per window, shared by every subsystem** — profiling showed `GetVisibleWindows` cost ~35 Win32 calls per candidate window per 250ms cycle because `IsWindowValid`, `IsWindowFloating` and `IsFullscreenWindow` each re-read title/class/process/style/ex-style/rect (and `IsFullscreenWindow` allocated three lookup arrays per call). Added `_WinReg()`: a per-HWND record holding every fact (`valid`, `floating`, `fullscreen`, `appbar`, `movable`, `cloaked`, `plugin`, `tiny`, rect, style, monitor) computed ONCE, invalidated by a cheap signature (style/ex-style first, then rect — measured costs), a 1s TTL, or a Config generation bump. `_WinRegSnapshot()` publishes the records plus a movable-handle set per physics tick, so the O(n²) force loop, collision passes and movement pass make **zero** Win32 calls. Public predicates (`IsWindowValid`, `IsWindowFloating`, `IsFullscreenWindow`, `IsShellAppBarWindow`, `IsPluginWindow`, `IsTinyUtilityWindow`, `_IsPhysicsMovable`) are now views over the registry. `GetVisibleWindows` rewritten as a single pass: `IsWindowVisible` pre-filter, one record per window, indexed existing-window lookup (the old code rescanned `g["Windows"]` twice per candidate), monitor gate, no O(n²) walks. Measured: UWS 3254→696µs/call, GVW 3146→645µs/call, CDL 2900→576µs/tick.
- **2026-11-02: Energy now scores ACHIEVABLE displacement (root cause of permanent "chaos")** — measured: 96–99% of ticks reported `state=chaos` for 3+ minutes while 66% of one-second windows reported ZERO moves, energy frozen at exactly `0.1567` for 61 samples, and 9 settle + 2 chaos-watchdog force-settles (one every ~16s) that never converged. Cause: energy summed raw velocity (`vx²+vy²`) for every tracked window, but `CalculateWindowForces` clamps `targetX/targetY` to the work area and `ApplyWindowMovements` refuses to move active/manual-locked/snapping bodies — so a body pinned against an edge kept regenerating force it could never spend, and chaos pinned the force multiplier at 0.6 forever. Fix: energy is scored from the clamped target delta (what the visual layer can actually apply) and bodies AWM will skip are excluded from the sum. Result: 0% chaos, energy 0.0007.
- **2026-11-02: Idle gate — a settled layout costs nothing** — added a provable no-op detector: if no tracked window's real rect differs from our state by >2px, nothing is dragging/menuing/snapping, the tracked set is unchanged and stored energy is below what `ApplyWindowMovements` could ever turn into a 1.5px move (per-window bound `(1.5/0.45)²`, derived from AWM's own smoothing alpha and threshold), the force/collision pipeline is skipped entirely. `ApplyWindowMovements`' external-move resync sets `g["_layoutDirty"]` so a user nudge wakes the engine within one tick. Validated live: `state=idle` at 64Hz heartbeat, woke to `state=normal` with 105/86/83 moves/s after moving a tracked window, then settled back to idle.
- **2026-11-02: AHK timer quantization measured — 16ms is a dead spot** — isolated-process sweep with and without `timeBeginPeriod(1)` (which makes no difference): request 1–15ms → **15.71ms (64Hz)**, 16ms → **25.16ms (40Hz)**, 17–30ms → 31.59ms (32Hz), 33ms → 47.63ms (21Hz). AHK v2 does not use one Win32 timer per script timer; it polls against `GetTickCount()` whose granularity is 15.625ms, so 16ms sits 0.375ms above a tick boundary and phase jitter produces a bimodal mix of one-tick and two-tick intervals. `PhysicsTimeStep`/`VisualTimeStep` now default to **15** (64Hz) with the measured table documented in Config and the settings tooltip; the user's persisted config was migrated 16→15.
- **2026-11-02: `SWP_ASYNCWINDOWPOS` for cross-process moves** — synchronous `SetWindowPos` made every frame pay the slowest managed app's message latency. Config-gated (`AsyncWindowPos`, default on). Because the flag posts the request, the on-screen rect can lag one command behind: `ApplyWindowMovements` now keeps a two-deep command history (`lastPositions`/`prevPositions`) and treats a match against the previous command as "our move is still landing" instead of an external move (which would zero momentum and set the layout dirty).
- **2026-11-02: Shell AppBars and DWM-cloaked windows are never physics bodies** — `IsShellAppBarWindow` detects taskbar replacements (RetroBar) by matching the exact band the shell reserves between monitor edge and work area (self-verifying: zero thickness when no AppBar is registered; verified precise against the live desktop with no false positives). `DwmGetWindowAttribute(DWMWA_CLOAKED=14)` rejects ghost UWP frames that keep `WS_VISIBLE` but are not on screen.
- **2026-11-02: `_DiagnoseIdlePhysics` was unreachable** — it required `_awmQuietTicks >= 60`, but that counter resets on every once-per-second flush at ~40 ticks/s, so a 3-minute zero-move stretch produced no `IdleDiag` line. Now time-based (2s of quiet) and throttled to once per 10s.
- **2026-11-02: Instrumentation for previously invisible work** — new profiler spans `GMP` (dropdown-menu scan), `GDM` (drag detect), `POP` (popup scan/owners), `CMP` (companion scan); the physics tick log now reports the measured `period=X.Xms`, and `ApplyWindowMovements`' crash log includes the failing line number.
- **2026-11-02: Fixed `RunAsAdmin` infinite relaunch loop** — `_IsElevated()` requested TOKEN_ADJUST_DEFAULT (0x20) instead of TOKEN_QUERY (0x8), so `GetTokenInformation` failed and the process always reported "not elevated"; with `RunAsAdmin` true the app relaunched itself forever. Fixed the access right and added a `--fwde-elevated` command-line marker so the relaunch can only ever happen once.
- **2026-11-02: New parameter defaults + maximal parameter audit** — adopted the user's tuned settings (Damping 0.1429, ManualRepulsionMultiplier 15, PairSmallWindowBoost 0.5, RepulsionImpulseScale 6.92, ResizeDelay 1, RunAsAdmin on, SeedDiagonalStep 200, SeedDiagonalMaxSteps 50, SeedJitterRange 100, SmallWindowReferenceDim 507, SmallWindowThresholdW 507, SmallWindowThresholdH 504, UserMoveTimeout 50). Removed dead params (`ManualGapBonus`, `NoiseScale`, `NoiseInfluence`, `ManualWindowColor`) and the stale `ManualWindowAlpha` override; fixed `DesktopIconPhysics` never appearing in the GUI (missing from `ShouldTreatAsBoolean`); widened ranges so no default sits on a slider bound; added a default-in-range guard and load-time clamping; documented all 50 params in hover help and README; restored alphabetical spec ordering (matches `FWDE_Config.json` and the settings window). Regenerated `FWDE_Config.json`.

- **Steam windows are now manageable** — research confirmed Steam's UI runs in CEF `steamwebhelper.exe` with class `SDL_app` and custom chrome. It was (a) flagged `fullscreen` because `SDL_app` is a fullscreen-game class and `steamwebhelper.exe` was in `fullscreenProcesses`, and (b) would have been floated by rule 7 (WS_POPUP, no caption). Added `steam.exe`/`steamwebhelper.exe` to `IsFullscreenWindow`'s `manageableProcesses` (removed from `fullscreenProcesses`) and to the default `ForceTrackProcesses` config so Steam is always managed. True Steam popups/dialogs still handled by popup cohesion (checked first).
- **Elevated-window (UIPI) support** — Steam (`steamwebhelper.exe`), Notepad++ [Administrator], and elevated FileZilla showed as `invalid` because they run ELEVATED while FWDE runs non-elevated: Windows UIPI makes style/minmax queries throw "Access is denied" and blocks SetWindowPos. Added:
  - `_GetWindowExcludeReason()` — Ctrl+Alt+D now reports the precise reason (`invalid:minimized/maximized/toolwindow/not-visible/no-title/fullscreen/access-denied-elevated`)
  - New opt-in config `RunAsAdmin` — when enabled and FWDE isn't elevated, FWDE relaunches itself elevated at startup (Run '*RunAs') so it can manage elevated windows; debug output shows a NOTE when elevated windows are present
- **Fixed: AHK GUI / Steam-style windows wrongly floated** — `FloatStyles` (WS_POPUP) floated ANY popup-styled window, but AHK v1 GUIs (`AutoHotkeyGUI`, e.g. Ahk2Exe) and custom-chrome apps (Steam) use WS_POPUP + WS_CAPTION (they look like normal windows) → FWDE never managed them. `IsWindowFloating` rule 7 now requires no WS_CAPTION for the WS_POPUP float. Ctrl+Alt+D now lists untracked non-floating windows with the exact exclusion reason (owned-popup / fwde-self / companion / invalid / monitor-filter).
- **Fixed: self-moving apps freezing physics** — `WindowMoveHandler`/`WindowSizeHandler` refreshed `ActiveWindow`/`LastUserMove` on EVERY app-initiated WM_MOVE/WM_SIZE, so self-repositioning apps (e.g. DarkTide launcher realigning its decorate layer) became permanently "active" and frozen by the active-window protection (energy built, 0 moves, settle loop). Now only real button-held drags/resizes mark a window active or auto-lock it; app-initiated moves still sync position. Added `_DiagnoseIdlePhysics()` — when energy is elevated but 0 moves persist for ~1s, logs each tracked window's skip reason (minmax/popup-freeze/active/manual-lock/snap/resync/at-target/should-move) to `FWDE_debug.log` as `IdleDiag — …`.
- **Same-App Companion Cohesion** — decorate/overlay layers (e.g. Warhammer 40K DarkTide launcher) no longer get pushed off their main window:
  - `AreCompanionPair()`: same process + same WPF `HwndWrapper[exe;;guid]` family + partial overlap (low floor so already-drifted layers pair) + similar size; generic fallback requires an overlay-style window (WS_POPUP, no WS_CAPTION) to avoid gluing unrelated stacked windows
  - `ScanCompanionWindows()`: connected-component grouping, largest window = anchor, others = companions (registry `_companionRegistry`)
  - `SyncCompanionWindows()`: lockstep-follows anchor's exact delta each tick (physics, drags, external moves) — NO host freeze (permanent layer, unlike popups)
  - Companions excluded from independent physics in `GetVisibleWindows`; failsafe in HealthMonitor; dashboard + Ctrl+Alt+D observability
  - Config: `CompanionFollowEnabled`, `CompanionScanIntervalMs`, `CompanionMinOverlap`, `CompanionMaxSizeRatio`; ToggleArrangement resets companion history
  - Shared `_IsSelfWindow()` helper now used by popup detection, GetVisibleWindows, and companion scan
- **Owned-Popup Cohesion** — browser permission bubbles ("Chrome Legacy Window") no longer drift from their host while FWDE is active:
  - `IsOwnedInteractivePopup()` detection: GW_OWNER + Chromium/Firefox/dialog class + style/title heuristics, with system-chrome and self-process (FWDE's own GUI) exclusion
  - `ScanOwnedPopups()` throttled registry (popup → owner); popups excluded from independent physics in `GetVisibleWindows` so physics never fights the browser's own anchoring
  - `SyncOwnedPopups()` lockstep movement — re-applies the owner's exact movement delta each tick (covers physics moves, user drags, external moves), no smoothing lag
  - `_popupOwners` host freeze wired into CalculateDynamicLayout, CalculateWindowForces, ApplyWindowMovements, ResolveFloatingCollisions, ResolveOverlapsDirect so popup buttons stay clickable while open
  - HealthMonitor popup-registry failsafe + status dashboard + Ctrl+Alt+D debug output for popup tracking
  - Config keys: `PopupFollowEnabled` (bool), `PopupFreezeHost` (bool), `PopupScanIntervalMs` (number) — exposed in the parameter settings GUI
  - ToggleArrangement resets popup history so lockstep deltas never carry stale positions across toggles
